B · Playful / study-themed

Layout Each example is an “index card” with a tiny rotation (±0.6°), a colored top edge, and a row of numbered cells — like flashcards laid on a desk. Done cells are sage-filled, the next cell glows accent. Caption spells out the resulting display in plain words. Hierarchy Serif task name → cell row (the visual explanation) → caption with the mono “Next: …” string → the app’s real progress bar, tying the teaching graphic back to what the task row actually shows. Mobile Cells shrink to 18×22px and wrap to a second line for 14 units; rotations reset to 0 below 480px to save width. Classes .hp-card .hp-head .hp-unit .hp-row .hp-cell (+.done/.next) .hp-caption Interaction Cards lift 2px on hover (rotation eases to 0). Optional: clicking a cell in the example marks it done live — a 5-second sandbox that teaches the tick gesture before the tutorial.

Recommendation

Ship B for the Planner, C everywhere else

B (index cards) is the best teacher for new users: the numbered-cell row makes “units are countable pieces” self-evident — you can literally see 3 done, 1 glowing next, 6 waiting — without reading a word. It also mirrors the exact gesture the tutorial teaches (tick one cell), so the modal and the app reinforce each other. The rotations and colored edges keep it friendly without leaving the app’s restrained dark style.

C (ledger) is the right default for other pages’ guides where examples are secondary — it’s dense, scannable, and trivially reusable as one component with a rows prop.

A is the safe middle ground if you want a single component for all pages; its cause→effect split is clearer than B on very small screens.
